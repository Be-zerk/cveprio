# Prioritization rules

Implemented in `cveprio/prioritize.py`; tested in `tests/test_prioritize.py`.
No weights or scores. Three categorical factors, a two-step table, and gates.

## Factors

**Exploitation** (from evidence)

| Value | Condition |
|---|---|
| `confirmed` | Listed in CISA KEV, or CISA SSVC `Exploitation=active` |
| `elevated` | Public exploit/PoC *claimed* (NVD "Exploit"-tagged reference, CNA "exploit" tag, or SSVC `poc`), or EPSS ≥ 0.10, or — the only AI path — validated AI rating "difficulty low" with ≥ 2 cited claims while nothing else signals exploitation |
| `evidence_incomplete` | KEV/NVD/EPSS retrieval failed so exploitation cannot be judged |
| `low_observed` | Sources retrieved, no signal found. **Not** "safe" |

EPSS 0.10 means "≈10% estimated probability that exploitation activity is observed in the
next 30 days". It was chosen because it is far above the median EPSS score (most CVEs
are < 0.01) while still well below "near certain". It is an assumption; change
`EPSS_ELEVATED` if your organisation prefers another cut-off.

**Severity** — the most severe base score of the newest CVSS version available
(CNA, ADP and NVD scores are all kept; disagreements are reported). Bands:
critical ≥ 9.0, high ≥ 7.0, medium ≥ 4.0, low > 0, `unscored`.

**Exposure** (from inventory + context, computed locally)

| Value | Condition |
|---|---|
| `high` | an affected asset is internet-facing **or** criticality high/critical |
| `standard` | affected assets are internal **and** criticality low/medium |
| `context_unknown` | an affected asset lacks `internet_facing` or `criticality` |
| `reduced` | high/standard, but an operator-declared compensating control applies (not verified by the tool) |
| `not_assessed` | no inventory supplied (single-CVE mode) |
| `needs_review` | no asset definitely affected, at least one ambiguous |
| `not_affected` / `not_in_inventory` | all matches not affected / no matching software |

With several affected assets, the most exposed one counts (high > context_unknown > standard > reduced).

## Decision

1. **Record gate**: rejected → `NO_ACTION_REJECTED`; reserved/not found → `INVALID_OR_UNPUBLISHED`; record unretrievable → `RETRIEVAL_FAILED`.
2. **Base**: confirmed → P1 · elevated → P2 · evidence_incomplete → P2 · low_observed → P3 if severity is critical/high/unscored, else P4.
3. **Exposure adjustment**: high → one step up (max P1) · reduced → one step down (never below P2 when confirmed) · standard/context_unknown/not_assessed → unchanged (the last two are marked *provisional*).
4. **Applicability gate**: needs_review → `NEEDS_REVIEW` (shows "would be Px if affected") · not_affected → `NOT_APPLICABLE` · not_in_inventory → `NOT_IN_INVENTORY`.

| Meaning (suggested; set your own SLAs) | |
|---|---|
| P1 | act now: emergency change / out-of-band patch |
| P2 | next patch cycle, ahead of routine work |
| P3 | scheduled maintenance |
| P4 | backlog / monitor |

## Why this shape

- **Known exploitation dominates** (KEV → P1 regardless of CVSS). KEV catalogue 2026.10.08
  lists 1,739 CVEs — a small fraction of all published CVE records — so a KEV listing is a
  strong, specific signal.
- **Severity only matters when there is no exploitation signal**, to separate "critical
  but quiet" (P3) from "medium and quiet" (P4).
- **Exposure moves one step**, so context can never turn a known-exploited issue into
  backlog, and a quiet issue on an internet-facing box rises only one level.
- **Uncertainty never lowers priority silently**: failures → P2 base; unscored → not low;
  missing context → provisional.

## Severity-only baseline

critical → P1, high → P2, medium → P3, low → P4, unscored → `UNSCORED`. It is computed for
every report so the effect of context is visible.

## Counterfactuals

"What would change the recommendation" is generated by re-running `decide()` with a single
input changed (e.g. exploitation → confirmed, exposure → high, exposure → not_affected) and
listing only changes that alter the outcome.

## Known limitations

- No notion of attack *type* beyond CVSS: a supply-chain backdoor without KEV listing on an
  internal asset gets P2 (the evaluation documents this disagreement with the reference).
- DoS vs RCE is not distinguished beyond the CVSS base score.
- Compensating controls are taken on trust from the inventory and only labelled.
- One-step adjustments are a design choice, not an empirically fitted model.
